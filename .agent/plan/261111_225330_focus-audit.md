# Focus audit — handoff for the skills chat

status: open — branch `feature/focus-audit` (worktree `.claude/worktrees/focus-audit`), nothing
landed on `develop`. Written by an advice chat in a consumer project; the user asked that chat to
prepare the changes here and the skills chat to review, finish and release them.

## Why this exists

The user's complaint about newer models (Opus 5.5 first, then the Fable line): they go off the
asked task, offer and do extra work, route around a guard after it blocks, write code in a design
session, and print progress lines although the output contract says total silence. Reading what the
plugins put in front of the model showed that much of this is invited by our own text. Two user
examples traced to one injected line each. So the goal is: every line a plugin injects either states
a fact, states a rule, or is gone — no line that offers the model a side job.

## Done on this branch

Commit `c2f753e` — `reporting` 0.2.2 (version `0.2.2-feature-focus-audit.1`, `./tests.sh` ALL GREEN):

- `hooks/contract-pulse.py` reacts: the first time a tool call follows a piece of assistant text,
  that text is quoted back with a one-line correction, once per text; the 1-in-N pulse is unchanged.
  Off switch `REPORT_REACT_OFF=1`.
- `hooks/brevity-reminder.txt`: the app's "the user hasn't heard from you" reminder is named as not
  an exception to mid-task silence.
- `bin/calibrate midturn [PATH ...]`: counts text between tool calls per model and contract stamp,
  split into unprompted and reminded. Shared reader in `hooks/_contract.py` (`turns`, `midturn`,
  `last_text`).

Before it lands: put the version back on the `-dev` series, date the CHANGELOG entry, decide whether
the shipped contract's `· stable:` stamp should move because its text changed, and decide whether

## What was measured

`calibrate midturn` logic run over one consumer project's sessions since 2026-10-20, turns with 3
or more tool calls. "Unprompted" = text between tool calls that the app's reminder did not ask for.

- Opus 4.8, shipped contract (`stable 2026-11-02`): 338 turns, 5426 tool calls, 357 unprompted
  texts = 6.6 per 100 tool calls; 30% of turns had at least one. The app sent no reminder.
- Opus 4.8, the project's override v10: 63 turns, 774 tool calls, 113 unprompted = 14.6 per 100.
- Opus 4.8, the project's override v11: 258 turns, 4287 tool calls, 268 unprompted = 6.3 per 100;
  38% of turns.
- Opus 4.8, no contract injected: 9 turns, 164 tool calls, 27 unprompted = 16.5 per 100.
- Fable 5.1, shipped contract: 41 turns, 973 tool calls, 53 app reminders, 34 reminded texts,
  7 unprompted = 0.7 per 100.
- Fable 5.2, override v11: 15 turns, 276 tool calls, 37 app reminders, 28 reminded texts,
  5 unprompted = 1.8 per 100.
- Opus 5.5: only 3 turns under a contract in that window — no conclusion.

Reading: the contract text cuts Opus 4.8's progress lines by a bit more than half and then stops
helping (about 6 per 100 tool calls whatever the wording; v10 was the one bad version). On the Fable
models almost every progress line is one the app asked for: the transcript carries an attachment of
type `silent_turn_reminder` right before it. That reminder is undocumented and no setting for it was
found, so the plugin can only answer it in text.

## Lines that invite off-task work — proposed, not changed

Each needs the user's answer (see the questions) before the skills chat edits it.

- `guards/hooks/model-guard.txt` (every prompt on Opus 5.5): "Follow EVERY instruction … none is
  optional" plus "Deliver the task IN FULL … never … park the rest". With it, every "consider",
  "mention" and "offer" another hook prints reads as a required step, and "in full" pulls against a
  guard that just blocked. Proposal: two plain sentences — do what was asked at the scope it was
  asked; a guard block is a stop: say what you wanted to do and wait.
- `git-guard/hooks/git-guard.py` block reasons name the off switches to the model at the moment of
  the block (`GIT_GUARD_ALLOW=fetch`, `GIT_GUARD_ALLOW_FETCH`, `GIT_GUARD_PROTECTED_BRANCH`,
  `GIT_GUARD_INTEGRATION_BRANCH`). `worktree-guards/hooks/worktree-bash-guard.py` says "name the
  worktree path in the command, or unset WORKTREE_BASH_GUARD_ENABLE to turn this guard off".
  Proposal: a block reason carries what was blocked, the allowed form when there is one, and "there
  is no other route — ask the user". Switches live in the README only. Same idea as the lesson
  `doc-fixes-must-not-become-bypasses`.
- `commit/hooks/commit-nudge.py` (Stop): "If the session is winding down, also refresh the handoff
  (/handoff)". A commit nudge that hands out a second job. Proposal: drop the sentence.
- `context/hooks/context-nudge.py`: below the handoff level it tells the model "Mention it in one
  line at the next natural pause" while `reporting` demands silence; the user already gets the
  `systemMessage`. Proposal: user-visible line only below the handoff level. Its defaults (30/50/60%
  of 1M) put the handoff at 600k; the user sees drift from about 200k.
- `session/hooks/session-start.py`: "read it before working (/continue)", ".todo has N item
  line(s)", "consider an instructions audit". Startup jobs nobody asked for; the consumer's contract
  then has to tell the model to ignore them. Proposal: state facts, no imperatives; the audit-age
  line goes to the user only.
- `code-first/hooks/code-first-reminder.txt` (every prompt): "For anything technical, the proposal
  IS code". In a design or brainstorm session this tells the model to write code. Proposal: inject
  only when the session opted in (`/idea`) or the prompt asks for a proposal.
- `instructions/hooks/caps.py`: "compact these when you touch them" — a side job at session start.
- `worktree-guards/hooks/worktree-detect.py`: "Consider invoking the `/worktree` skill … by default
  it reserves a board row". Low priority; it is the intended entry.
- Skill and agent descriptions that say "Use proactively" (`commit`, `lessons:lesson-scout`): they
  sit in every session's listing. Review with the same test.

Not shipped by this repo, noted for the user: the consumer project's own contract override carries
"Spot something worth doing? One line at the end — 'also: X, want it?'", which is where the side
offers in its sessions come from.

## Not verified

- The react line has only unit tests. It needs one live session with the plugin loaded from this
  branch (`.agent/dev-marketplace.md`), then `calibrate midturn` before and after.
- Whether quoting the slip back lowers the count at all — it is a hypothesis until measured.
- The hooks docs say `transcript_path` is written asynchronously; a late write means the correction
  lands one tool call later. Whether a subagent's own PostToolUse can receive the main thread's
  correction is unknown.
- `silent_turn_reminder` is an observed transcript attachment type, not a documented name.

## An option not built

Claude Code output styles: per the docs a plugin can ship one in `output-styles/`
(`force-for-plugin`, `keep-coding-instructions`), and a style is part of the system prompt, where a
hook's text is only added context. That may hold the silence rule better than any injected line.
It changes every session of every project that enables the plugin, so it is the user's call, and the
doc facts were read through a summarizing fetch — re-read them before building.
