# Focus audit — handoff for the skills chat

status: open — branch `feature/focus-audit` (worktree `.claude/worktrees/focus-audit`), nothing
landed on `develop`. Written by an advice chat in a consumer project; the user asked that chat to
prepare the changes here and the skills chat to review, finish and release them.

## Why this exists

The user's complaint about newer models (Opus 5.5 first, then the Fable line): they go off the
asked task, offer and do extra work, route around a guard after it blocks, write code in a design
session, and print progress lines although the output contract says total silence. Reading what the
plugins put in front of the model showed that much of this is invited by our own text. Two user
examples traced to one injected line each. So the goal is: every line a plugin injects either states
a fact, states a rule, or is gone — no line that offers the model a side job.

## Done on this branch — the reporting change

Commit `c2f753e` — `reporting` 0.2.2 (version `0.2.2-feature-focus-audit.1`, `./tests.sh` ALL
GREEN):

  that text is quoted back with a one-line correction, once per text; the 1-in-N pulse is unchanged.
  Off switch `REPORT_REACT_OFF=1`.
- `hooks/brevity-reminder.txt`: the app's "the user hasn't heard from you" reminder is named as not
  an exception to mid-task silence.
- `bin/calibrate midturn [PATH ...]`: counts text between tool calls per model and contract stamp,
  split into unprompted and reminded. Shared reader in `hooks/_contract.py` (`turns`, `midturn`,
  `last_text`).

Before it lands: put the version back on the `-dev` series, date the CHANGELOG entry, decide whether
the shipped contract's `· stable:` stamp should move because its text changed, and decide whether
the `calibrate` skill should call `calibrate midturn` in its `compare` step.

## What was measured

`calibrate midturn` logic run over one consumer project's sessions since 2026-10-20, turns with 3
or more tool calls. "Unprompted" = text between tool calls that the app's reminder did not ask for.

- Opus 4.8, shipped contract (`stable 2026-11-02`): 338 turns, 5426 tool calls, 357 unprompted
  texts = 6.6 per 100 tool calls; 30% of turns had at least one. The app sent no reminder.
- Opus 4.8, the project's override v10: 63 turns, 774 tool calls, 113 unprompted = 14.6 per 100.
- Opus 4.8, the project's override v11: 258 turns, 4287 tool calls, 268 unprompted = 6.3 per 100;
  38% of turns.
- Opus 4.8, no contract injected: 9 turns, 164 tool calls, 27 unprompted = 16.5 per 100.
- Fable 5.1, shipped contract: 41 turns, 973 tool calls, 53 app reminders, 34 reminded texts,
  7 unprompted = 0.7 per 100.
- Fable 5.2, override v11: 15 turns, 276 tool calls, 37 app reminders, 28 reminded texts,
  5 unprompted = 1.8 per 100.
- Opus 5.5: only 3 turns under a contract in that window — no conclusion.

Reading: the contract text cuts Opus 4.8's progress lines by a bit more than half and then stops
helping (about 6 per 100 tool calls whatever the wording; v10 was the one bad version). On the Fable
models almost every progress line is one the app asked for: the transcript carries an attachment of
type `silent_turn_reminder` right before it. That reminder is undocumented and no setting for it was
found, so the plugin can only answer it in text.

## The user's decisions (2026-11-11)

- Total silence while working. No "one line on long turns".
- Replace the per-prompt trust text with a plain scope text; a guard block means stop and ask.
- Block reasons never name an off switch; switches live in the READMEs.
- Code-first applies only after `/idea`, or to one prompt that asks for a proposal.
- Housekeeping lines are not shown at session start. They are shown at the end, and not at all in a
  worktree: "if I am in a cleaning worktree, I will say cleanup things".
- Context levels: 200k hint, 300k action, 550k red alert.
- The consumer project drops its own "also: X, want it?" line (done in that project, not here).

## Done on this branch — the decisions, one commit per topic

Every changed plugin carries a `-feature-focus-audit.1` version and a `## <version> — unreleased`
CHANGELOG entry; `./tests.sh` is ALL GREEN at `1a28dfc`.

- `0ef945e` — `guards`, `git-guard`, `worktree-guards` (+ the vendored copy in `runners`), `todo`,
  `patterns`. `guards/hooks/model-guard.txt` is now a SCOPE GUARD: asked scope only, say a
  disagreement in one sentence and carry on, finish the whole task or say which part is missing, a
  block is a stop. Every block reason was rewritten to: what was blocked, the allowed form when one
  exists, else "Stop and tell the user what you wanted to do." No reason names an env switch (tests
  assert it). The leak detector no longer prints a command that discards a file in the main
  checkout.
- `d0a5683` — `session`, `instructions`, `upkeep`. SessionStart keeps only the branch line and the
  "python3 not found" warning. Handoff age, `.todo` count, audit age, cap breaches, the meta-lint
  count (`meta-lint --end-note`) and plugin updates are a `systemMessage` at Stop: user-visible,
  never blocking, once per session per distinct fact, silent in a linked worktree unless
  `NUDGES_IN_WORKTREE=1`. `meta-lint --stop` (the block on what a session wrote) is untouched.
- `d2ab991` — `code-first`. The contract and the inline-code Stop guard apply only when the prompt
  starts with `/idea` or `/code-first:idea` (sticky for the session), or one prompt matches
  `CODE_FIRST_TRIGGER_PATTERN` (default propose / proposal / sketch), or `CODE_FIRST_INJECT=always`.
  The stale-idea line moved to Stop as a user note.
- `0aa5d60` — `context`. Defaults `20,30,55`; the hint goes to the user only; the last level is a
  red alert ("finish the step, start nothing new"). An answer to a nudge is read only from a prompt
  of 200 characters or fewer.
- `8b783bf` — `commit`. The nudge no longer adds "also refresh the handoff".
- `1a28dfc` — root `README.md` and `marketplace.json` synced.

## For the skills chat to decide or finish

- Versions: every changed plugin needs its `-dev` series back before landing, and the CHANGELOG
  entries need dates. Agents bumped the patch (`0.1.0` → `0.1.1-feature-focus-audit.1`).
- `instructions`: `caps` no longer blocks at Stop, so a project without `.agent/meta-lint.json` has
  no Stop gate on caps. `meta-lint --end-note` runs every enabled check on every Stop (the marker
  only dedupes the output); `--fast` used to run once per session. Comments around `stop_mode`
  still say it "mirrors the caps Stop hook".
- `code-first`: the `idea` skill description no longer triggers on design talk (`d9a23c9`, user:
  "cut it"). Still open: the Stop guard never fires on the `/idea` turn itself, because the default allow pattern contains
  `command` and the transcript form of a slash-command turn contains `<command-name>`. The docs
  describe a `UserPromptExpansion` event that carries the command name; it may be a cleaner way to
  set the session marker.
- `context`: the bug behind the 200-character rule was seen live — a subagent's report that quoted
  'topic done' was read as the user's answer and silenced the nudges for the session. Other hooks
  that scan the prompt (`todo`'s "ALLOW TODO" scan) may have the same hole: UserPromptSubmit also
  fires for subagent reports and cross-session messages.
- `reporting`, the shipped contract (`hooks/brevity-reminder.txt`) — lines that can set a wrong
  idea, not changed here: "If it needs background to answer, you're not done: pick, state the
  assumption, move on" tells the model to decide a fork by itself instead of asking; "options I
  didn't ask for (one recommendation max)" still allows one unasked recommendation. The consumer
  project fixed three such lines in its own override on the same day, and the user prefers that
  override's tone: its GOOD example ended with an offer ("Q: run it now?") — an example is copied
  more than any rule; "do the least work that answers me" made short reports come from shallow
  work, now "don't go wider than the question; inside it, do the work properly"; and one line is
  allowed when a turn must end while background work still runs (a turn cannot end with nothing).
  Decide with the user whether the shipped text takes these over.
- `commit`: `commit-format` blocks on text, not on commits. It denied a Bash command whose only
  commit was single-line because a Python heredoc earlier in the same command had newlines, and it
  denied a second command that made no commit at all because the heredoc's prose quoted a commit
  command. Splitting the calls, and using the Edit tool for the prose, passed.
- `upkeep`: the user line still ends "— /upkeep to apply." It checks once per session, at the first
  Stop.
- `session/README.md` still lists a planned "stop-nudge hook". `commit-format` still prints
  "BLOCKED:" in capitals where `git-guard` now prints "blocked:".
- `instructions/examples/meta-lint.rabbit-run.json` carries a project name in shipped content
  (older than this branch).
- Skill and agent descriptions that say "Use proactively" (`commit`, `lessons:lesson-scout`) were
  not reviewed.
- One agent's shell command was denied by the live `todo` guard: a heredoc that held the test
  fixture text `echo x >> .todo`. The deny reason named the skip prefix. The agent did not use it
  and made the edit with the Edit tool. That old reason is one of the texts this branch rewrites.

## Not verified

  (`.agent/dev-marketplace.md`) and check: the react line arrives and lowers the count
  (`calibrate midturn` before and after); a Stop hook's `systemMessage` shows to the user and stays
  out of the model's context (the docs call it a "Warning message shown to the user" and do not say
  the second part); `/idea` reaches UserPromptSubmit as typed (the docs say so; the plugin-qualified
  form is not documented).
- The hooks docs say `transcript_path` is written asynchronously; a late write means the react
  correction lands one tool call later. Whether a subagent's own PostToolUse can receive the main
  thread's correction is unknown.
- `silent_turn_reminder` is an observed transcript attachment type, not a documented name.
- All Claude Code doc facts in this file were read through a summarizing fetch.

## An option not built

Claude Code output styles: per the docs a plugin can ship one in `output-styles/`
(`force-for-plugin`, `keep-coding-instructions`), and a style is part of the system prompt, where a
hook's text is only added context. That may hold the silence rule better than any injected line.
It changes every session of every project that enables the plugin, so it is the user's call.
